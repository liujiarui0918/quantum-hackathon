# 混合整数优化问题赛道求解思路速读

队伍：平步青云  
当前提交主线：MIQP-aware Route 7

## 一句话思路

这题真实目标是最大化：

```text
maximize x^T Q x + c^T x + h^T y
subject to A x + G y <= b
           B x <= b'
           x in {0,1}^n, y >= 0
```

不要把连续变量 `y` 离散化塞进大 QUBO。正确主线是：让量子/退火/学习引导方法搜索二进制 `x` 的高价值 block，固定 `x` 后用 LP 精确求 `y`。

## Pipeline

```text
official .npz
  -> MiqpInstance
  -> binary variable scoring
  -> block selector, <=20 bits by default
  -> warm-start probabilities
  -> variable ranking / fixing plan
  -> block QUBO
  -> exact / annealing / learning-guided / QAOA-compatible backend
  -> candidate x
  -> solve continuous LP for y
  -> feasible objective and Benders-style cut advice
  -> next block
```

## 为什么这样做

- `x` 是组合爆炸来源，适合量子优化或量子启发搜索。
- `y` 在固定 `x` 后是线性规划，经典 LP 求解器更精确。
- 全量 QUBO 会因为连续变量离散化和约束 penalty 变得很大，很容易超过可模拟或可运行的 qubit 规模。
- block QUBO 可以稳定控制在 20 到 30 qubit 内，更符合当前 QAOA/Aer/退火的实际资源边界。

## 关键代码

- `src/quantum_hackathon/miqp/model.py`：MIQP 数据结构、目标函数、可行性检查。
- `src/quantum_hackathon/miqp/loader.py`：读取官方 `.npz`。
- `src/quantum_hackathon/miqp/route7.py`：block selector、warm-start、LP 子问题、cut advisor、主循环。
- `src/quantum_hackathon/miqp_cli.py`：官方样例的 CLI 入口。
- `src/quantum_hackathon/solvers/qaoa/`：QUBO 到 Ising、QAOA ansatz、Aer/backend 接口。
- `scripts/render_miqp_results.py`：把结果 JSON 渲染成 Markdown 表格。
- `scripts/miqp_baseline_study.py`：横向 baseline、资源画像和论文插图。
- `scripts/miqp_selector_ablation.py`：block selector 权重和聚类策略消融。
- `scripts/miqp_trace_blocks.py`：运行 route7++ 并记录 block-level trace，可作为训练数据。
- `scripts/miqp_synthetic_suite.py`：生成 MIQP-like synthetic `.npz`，覆盖不同 Q 密度、B 选择约束和连续 LP 耦合。
- `scripts/miqp_train_block_model.py`：从 trace JSONL 训练非神经线性 block scorer；当前最终主线不使用 GNN/RL。
- `scripts/miqp_auto_sota.py`：对每个真实实例跑多配置赛马，自动选择最高可行目标值。

## 新增横向对比和图

`submission/baseline_study/` 里有一套更像论文实验的横向 study：

- `miqp_baseline_study.md`：可读表格。

关键结论：样例 B 上，简单贪心 gap 约 10.78%，block-QAOA 单步候选 gap 约 20.02%，而增强后的 MIQP-aware route7++ 达到官方最优。这说明优势主要来自 MIQP-aware 的 block + LP + cut 组合，而不是单独堆一个量子线路。

新增基线还包括 `genetic_repair_lp` 和 `binary_pso_repair_lp`。样例 B 上 GA 达到 `565.761894`，gap 约 `7.29%`，仍弱于 route7++ 的 `610.266639` / `0.00%`。`global_binary_sa_lp` 在 B 样例中不是漏跑，而是因为 `n=80` 超过全局 32-bit QUBO 上限，脚本明确标记 skipped。

## 六点落地状态

- 连续变量经典化：已落地，`y` 交给 LP。
- 结构化 subQUBO 切块：已扩展为 route7++ block pool，按 `Q/A/B`、目标边际、cut 信息和历史 improvement 排序，不随机切。
- 约束保持 mixer：已加入 XY-swap proxy、2-swap、destroy/repair、repair 后容量补齐和 local branch 候选；完整 XY mixer circuit 仍不是主提交依赖。
- 学习指导扩展：已有可插拔 weights、cluster selector、solver portfolio、fixing plan、block trace 和非神经线性 block scorer；由于真实标签太少，GNN/RL 不进入当前最终主线。
- 求解器 portfolio：已落地，exact / learning-guided / annealing / 小块 QAOA-compatible 接口；auto SOTA 会按可行目标值选择最终解。
- 浅层 QAOA：已落地，默认 `p=1`，后续可用 GPU 对小块调 `p=1,2,3`。

## route7++ 和 auto SOTA

明早 8 点真实数据发布后，优先运行：

```bash
python scripts/miqp_auto_sota.py \
  --inputs "path/to/test_*.npz" \
  --output-dir results/auto_sota \
  --profile safe \
  --seeds 3,7,11,19 \
  --max-lp-evals 800
```

该脚本默认只跑非神经配置，并支持 `--profile quick|safe|deep`。每个实例只取最高可行目标值；`--learned-block-model` 仅作为赛后/离线消融接口，不作为当前提交主线。

预算敏感性实验显示，B 样例 `max_lp_evals=180` 时 `route7pp_balanced/cluster` 得到 `594.648146`，继续加到约 `768` 次 LP 评估后达到官方最优 `610.266639`。这说明 repair 后容量补齐、候选代理排序、block pool 和迭代预算共同有效。

## 后续最值得优化的地方

1. 把 block selector 从启发式升级为 learned selector。
2. 用 exact / annealing / hybrid solver 给模拟图数据打标签，训练 `graph -> bit probability` 模型。
3. 把 cut advice 反馈到下一轮 block 选择，而不是只写入诊断。
4. 对 B 类大实例做多 seed、多 block destroy/repair、局部分支搜索。
5. 若有真实量子 backend 或 Aer GPU 时间，把 QAOA 只跑在小 block 上，不跑全量大 QUBO。
