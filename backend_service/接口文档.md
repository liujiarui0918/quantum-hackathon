## 1. 快速概览

| 方法 | 路径 | 功能 | 认证 |
|------|------|------|------|
| `GET` | `/health` | 服务健康检查 | 无 |
| `GET` | `/api/quantum/sample-problem` | 获取示例优化问题 | 无 |
| `POST` | `/api/quantum/solve` | 同步求解优化问题 | 无 |

- **Base URL**（开发环境）: `http://localhost:8000`
- **Content-Type**: `application/json`
- **字符编码**: UTF-8

---

## 2. 通用约定

### 成功响应格式

所有成功响应的顶层均包含 `"ok": true`：

```json
{
  "ok": true,
  // ... 具体数据字段
}
```

### 错误响应格式

所有错误响应的顶层均包含 `"ok": false` 和 `error` 对象：

```json
{
  "ok": false,                            // 固定为 false，表示请求失败
  "error": {
    "code": "invalid_problem",            // 机器可读错误码（英文常量）
    "message": "Failed to parse...",      // 人类可读错误描述（英文）
    "details": {}                         // 可选的上下文数据，类型为 object 或 null
  }
}
```

### 字段命名规范

- 所有 JSON 字段使用 **snake_case** 命名（与 Python 侧保持一致）
- 前端 TypeScript 接口定义中的字段名与后端完全一致，**不做 camelCase 转换**

## 3. 接口详情

### 3.1 健康检查 `GET /health`

用于探测服务是否正常运行，K8s liveness/readiness probe 可直接调用。

**请求示例**

```bash
curl http://localhost:8000/health
```

**响应体**

```json
{
  "status": "ok",           // 固定值 "ok"，表示服务健康
  "service": "backend_service"  // 服务标识名称
}
```

**HTTP 状态码**: `200`

---

### 3.2 获取示例问题 `GET /api/quantum/sample-problem`

返回仓库 `data/sample_problem.json` 的内容，可直接作为求解接口的 `problem` 字段使用。用于前端调试、表单默认值填充。

**请求示例**

```bash
curl http://localhost:8000/api/quantum/sample-problem
```

**响应体**

```json
{
  "ok": true,                    // 请求成功标记
  "problem": {                   // 示例优化问题，结构详见第 4 节
    "name": "sample_assignment", // 问题名称
    "sense": "maximize",         // 优化方向
    "variables": [               // 决策变量列表
      { "name": "model_a", "kind": "binary" },
      { "name": "model_b", "kind": "binary" },
      { "name": "model_c", "kind": "binary" },
      { "name": "boost_x", "kind": "binary" },
      { "name": "boost_y", "kind": "binary" }
    ],
    "objective": {               // 目标函数
      "linear": {                // 线性项系数
        "model_a": 9.0,
        "model_b": 6.0,
        "model_c": 7.0,
        "boost_x": 3.0,
        "boost_y": 2.0
      },
      "quadratic": [             // 二次项列表
        { "variables": ["model_c", "boost_x"], "coefficient": 1.0 }
      ],
      "offset": 0.0              // 目标函数偏置（常数项）
    },
    "constraints": [             // 约束条件列表
      {
        "name": "choose_one_model",
        "linear": { "model_a": 1.0, "model_b": 1.0, "model_c": 1.0 },
        "sense": "==",
        "rhs": 1.0,
        "constraint_type": "exactly_one",
        "penalty_weight": 15.0
      },
      {
        "name": "resource_budget",
        "linear": { "model_a": 5.0, "model_b": 3.0, "model_c": 4.0, "boost_x": 2.0, "boost_y": 1.0 },
        "sense": "<=",
        "rhs": 6.0,
        "constraint_type": "bounded_sum",
        "penalty_weight": 20.0
      }
    ]
  }
}
```

**HTTP 状态码**: `200`

**错误场景**: 若 `data/sample_problem.json` 不存在，返回 `500` + `sample_problem_unavailable`

### 3.3 同步求解 `POST /api/quantum/solve`

核心接口。接收优化问题描述和运行参数，经过 QUBO 建模 → Exact → SA → QAOA → ConstrainedQAOA 四条路线求解，返回原始结果和前端可视化双层数据。

请求为**同步阻塞**：客户端需等待求解完成后才能收到响应（默认参数下通常 < 10 秒）。

**请求示例**

```bash
curl -X POST http://localhost:8000/api/quantum/solve \
  -H "Content-Type: application/json" \
  -d '{
    "problem": {
      "name": "sample_assignment",
      "sense": "maximize",
      "variables": [{"name": "model_a", "kind": "binary"}],
      "objective": {"linear": {"model_a": 9.0}},
      "constraints": [
        {"linear": {"model_a": 1.0}, "sense": "==", "rhs": 1.0, "constraint_type": "exactly_one"}
      ]
    },
    "run_options": {"seed": 7, "skip_qaoa": false}
  }'
```

**请求体结构**

```json
{
  // ========== problem: 优化问题定义（必填） ==========

  "problem": {
    "name": "string",              // 问题名称，用于标识和报告（必填）
    "sense": "maximize",           // 优化方向："maximize" | "minimize"（必填）
    "variables": [],               // 决策变量列表，至少 1 个（必填）
    "objective": {},               // 目标函数定义（必填）
    "constraints": []              // 约束条件列表（可选，默认为空）
  },

  // ========== run_options: 运行参数（可选，全部有默认值） ==========
  // 完整字段说明见第 5 节
  "run_options": {
    "seed": 7,                     // 随机种子，用于确保结果可复现
    "sa_reads": 60,                // 模拟退火读取次数
    "sa_sweeps": 150,              // 模拟退火每轮扫描次数
    "top_k": 20,                   // 返回的最优解数量
    "qaoa_p": 1,                   // QAOA 电路层数
    "qaoa_shots": 200,             // QAOA 采样次数
    "qaoa_max_qubits": 12,         // QAOA 最大量子比特数阈值（超出则跳过）
    "qaoa_grid_size": 5,           // QAOA 参数网格搜索粒度
    "qaoa_random_trials": 10,      // QAOA 随机初始点尝试次数
    "skip_qaoa": false             // 是否跳过 QAOA 路线
  }
}
```

**HTTP 状态码**

| 状态码 | 含义 |
|--------|------|
| `200` | 求解成功 |
| `400` | 问题定义无效（`invalid_problem`） |
| `422` | 请求参数校验失败（`VALIDATION_ERROR`） |
| `500` | 求解过程异常或服务器内部错误 |

## 4. problem 请求体完整字段说明

`problem` 对象描述一个完整的组合优化问题，是 `POST /api/quantum/solve` 的必填字段。其结构由 `src/quantum_hackathon/demo.py` 的 `problem_from_json()` 函数解析。

### 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `string` | **是** | 问题名称，用于报告标题和场景匹配。若以 `sample_assignment` 开头会触发场景特定字段生成 |
| `sense` | `"maximize" \| "minimize"` | **是** | 优化方向：最大化或最小化 |
| `variables` | `VariableSpec[]` | **是** | 决策变量列表，**至少 1 个**，不可为空 |
| `objective` | `ObjectiveSpec` | **是** | 目标函数定义 |
| `constraints` | `ConstraintSpec[]` | 否 | 约束条件列表，默认 `[]` |

### VariableSpec（变量定义）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `string` | **是** | 变量名称，需在 objective 和 constraints 中一致引用 |
| `kind` | `"binary" \| "integer"` | **是** | 变量类型：二进制变量或整数变量 |
| `lower` | `number` | 否 | 下界（仅 integer 类型），默认 0 |
| `upper` | `number` | 否 | 上界（仅 integer 类型），默认 1 |

```json
// 二进制变量（最常用）
{ "name": "model_a", "kind": "binary" }

// 整数变量
{ "name": "units", "kind": "integer", "lower": 0, "upper": 10 }
```

### ObjectiveSpec（目标函数）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `linear` | `object` | 否 | 线性项：`{"变量名": 系数, ...}`，缺省为 `{}` |
| `quadratic` | `object[]` 或 `object` | 否 | 二次项：数组形式 `[{"variables": ["a","b"], "coefficient": c}]` 或对象形式 `{"a,b": c}` |
| `high_order` | `object[]` | 否 | 高阶项列表，缺省为 `[]` |
| `offset` | `number` | 否 | 目标函数常数偏置，默认 `0.0` |

```json
// 完整示例
{
  "linear": { "model_a": 9.0, "model_b": 6.0 },
  "quadratic": [
    { "variables": ["model_a", "model_b"], "coefficient": 2.0 }
  ],
  "offset": 0.0
}
```

### ConstraintSpec（约束定义）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `string` | 否 | 约束名称，用于报告和 violation 诊断 |
| `linear` | `object` | **是** | 线性系数：`{"变量名": 系数, ...}` |
| `sense` | `"==" \| "<=" \| ">="` | **是** | 约束关系 |
| `rhs` | `number` | **是** | 右端常数 |
| `constraint_type` | `string` | 否 | 约束类型标签：`"exactly_one"`, `"bounded_sum"` 等。`exactly_one` 会触发 Constrained QAOA 的 one-hot 路线 |
| `hardness` | `"hard" \| "soft"` | 否 | 硬约束或软约束，默认 `"soft"` |
| `penalty_weight` | `number` | 否 | 罚函数权重系数，值越大违反代价越高 |

## 5. run_options 参数说明

`run_options` 对象的每个字段均为可选，有对应的默认值。默认值与 CLI `python -m quantum_hackathon.demo` 参数保持一致。

| 字段 | 类型 | 默认值 | 范围 | 说明 |
|------|------|--------|------|------|
| `seed` | `int` | `7` | `≥ 0` | 随机种子。相同 seed + 相同 problem 保证结果可复现 |
| `sa_reads` | `int` | `60` | `≥ 1` | 模拟退火的独立退火次数（越大越稳定，但耗时增加） |
| `sa_sweeps` | `int` | `150` | `≥ 1` | 每次退火的 Monte Carlo 扫描步数 |
| `top_k` | `int` | `20` | `≥ 1` | 各求解器保留返回的 Top-K 个最优样本 |
| `qaoa_p` | `int` | `1` | `≥ 1` | QAOA 变分电路的层数（p=1 通常足够小规模问题） |
| `qaoa_shots` | `int` | `200` | `≥ 1` | QAOA 线路的测量采样次数 |
| `qaoa_max_qubits` | `int` | `12` | `≥ 1` | QAOA 最大量子比特阈值。若问题所需 qubit 数超过此值，自动跳过 QAOA |
| `qaoa_grid_size` | `int` | `5` | `≥ 1` | 参数网格搜索的每维分辨率 |
| `qaoa_random_trials` | `int` | `10` | `≥ 1` | 从随机初始点出发的优化尝试次数 |
| `skip_qaoa` | `bool` | `false` | - | 强制跳过 QAOA 路线（`true` = 不运行 QAOA） |

```json
// 最简请求：全部使用默认值
{ "run_options": {} }

// 跳过 QAOA 以加速响应
{ "run_options": { "skip_qaoa": true } }

// 调高 SA 精度
{ "run_options": { "sa_reads": 200, "sa_sweeps": 500 } }
```

## 6. raw_result 响应体完整字段说明

`raw_result` 是 `demo.run_demo()` 函数的原始输出，包含 10 个顶层字段。以下逐一说明。

### 6.1 problem — 问题摘要

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | `string` | 问题名称 |
| `source` | `string` | 问题来源。API 调用时固定为 `"api:request"` |
| `sense` | `"minimize" \| "maximize"` | 优化方向 |
| `variables` | `string[]` | 变量名列表（仅名称字符串，不含类型等详细信息） |
| `num_logical_variables` | `int` | 原始逻辑变量数量 |
| `num_qubo_bits` | `int` | 编译为 QUBO 后的二元变量总数（含 slack 编码引入的额外比特） |

### 6.2 run — 运行信息

| 字段 | 类型 | 说明 |
|------|------|------|
| `seed` | `int` | 实际使用的随机种子 |
| `python` | `string` | Python 解释器版本 |
| `platform` | `string` | 操作系统平台标识 |
| `total_ms` | `float` | 端到端总耗时（毫秒），从 problem 输入到全部路线完成 |

### 6.3 diagnostics — 模型诊断

| 字段 | 类型 | 说明 |
|------|------|------|
| `diagnostics` | `object` | 自由格式的 JSON 对象。由 `QuboModel.diagnostics()` 生成，内容包括系数矩阵密度、slack 变量膨胀、系数比值警告等 |

### 6.4 best_solution — 最优解

| 字段 | 类型 | 说明 |
|------|------|------|
| `bitstring` | `string` | QUBO 空间的二进制字符串（如 `"100000"`） |
| `bits` | `int[]` | 同上的比特数组形式 |
| `logical_solution` | `object` | 解码回原始业务变量的字典：`{"变量名": 取值}` |
| `objective_value` | `float` | 原始业务目标函数值（已从 QUBO 解码还原） |
| `qubo_energy` | `float` | QUBO 模型的能量值（含惩罚项贡献） |
| `penalty_energy` | `float` | 惩罚项能量。`0` 表示所有软约束满足 |
| `is_feasible` | `bool` | 是否满足所有约束 |
| `total_violation` | `float` | 所有约束违反量的总和 |
| `num_occurrences` | `int` | 该解在采样中出现的次数 |
| `source_backend` | `string` | 产生该解的求解器（`"exact"`, `"simulated_annealing"`, `"qaoa_shot_simulator"` 等） |
| `constraint_violations` | `object[]` | 逐条约束的违反详情（结构见上文响应示例） |

### 6.5 benchmark — 求解器对比

| 字段 | 类型 | 说明 |
|------|------|------|

## 8. 错误码参考

所有错误响应格式为：

```json
{
  "ok": false,
  "error": {
    "code": "ERROR_CODE",    // 机器可读错误码
    "message": "...",        // 人类可读描述
    "details": {}            // 可选上下文
  }
}
```

| HTTP 码 | 错误码 | 触发条件 | 说明 |
|---------|--------|----------|------|
| `400` | `invalid_problem` | 变量列表为空、不支持的类型、必填字段缺失、JSON 格式错误 | 需检查 `problem` 字段定义是否符合第 4 节规范 |
| `422` | `VALIDATION_ERROR` | `run_options` 参数超出 Pydantic 范围校验（如 `seed < 0`） | `details` 中会包含具体校验错误列表 |
| `500` | `solve_failed` | 求解过程中抛出未预料的异常 | 检查 problem 数据一致性 |
| `500` | `sample_problem_unavailable` | `data/sample_problem.json` 文件不存在 | 确认仓库根目录下有 `data/` 目录 |
| `500` | `INTERNAL_ERROR` | 未预期的服务器内部错误 | 查看服务端日志排查 |

### 错误响应示例

```json
// 400 - 问题定义无效
{
  "ok": false,
  "error": {
    "code": "invalid_problem",
    "message": "Failed to parse problem: input JSON must contain a non-empty variables list",
    "details": { "payload_keys": ["name", "sense", "variables", "objective"] }
  }

// 422 - 参数校验失败
{
  "ok": false,
  "error": {
    "code": "VALIDATION_ERROR",

    "details": [
      {
        "loc": ["body", "run_options", "seed"],

      }
    ]
  }
}

{
  "ok": false,
  "error": {
    "code": "solve_failed",
    "message": "Solver execution failed: ...",
    "details": null
  }
}
```

## 9. 前端接入方式

### 代理配置

前端 `front_end/next.config.ts` 通过 Next.js rewrites 将 `/api/quantum/*` 代理到 FastAPI：

```typescript
async rewrites() {
  return [
    {
      source: '/api/quantum/:path*',
      destination: 'http://localhost:8000/api/quantum/:path*',
    },
  ];
}
```

浏览器端调用时无需处理跨域，直接请求同源路径即可：

```typescript
// 前端调用示例
const res = await fetch('/api/quantum/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ problem, run_options: {} }),
});
const data: QuantumApiResponse = await res.json();
```

### TypeScript 类型定义

前端类型定义在 `front_end/lib/quantum-api-types.ts`，字段名与后端保持 snake_case 一致。主要类型接口：

| 后端概念 | 前端 TypeScript 接口 | 说明 |
|----------|---------------------|------|
| 顶层响应 | `QuantumApiResponse` | `{ok, raw_result, visualization}` |
| 原始结果 | `RawResult` | 10 个顶层字段 |
| 双层可视化 | `QuantumVisualization` | `{quantum: QuantumView, scenario: ScenarioView}` |
| 量子视图 | `QuantumView` | problem, best_solution, benchmark_rows, qaoa, constrained_qaoa, diagnostics |
| 场景视图 | `ScenarioView` | scenario_id, variables, constraints, objective_value |
| 最优解 | `PlaygroundBestSolution` | bitstring, logical_solution, objective_value, is_feasible 等 |
| 对比行 | `PlaygroundBenchmarkRow` | solver, status, best_feasible_objective, total_ms 等 |
| 错误响应 | `QuantumApiError` | `{ok, error: {code, message, details}}` |

> **重要提示**
>
> - 本服务为**同步阻塞 API**。所有求解在 CPU 本地完成，默认参数下通常数秒内返回。大规模问题或调高 QAOA 参数可能导致响应时间显著增加。
